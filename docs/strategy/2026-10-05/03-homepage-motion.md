# 首頁動畫改善方案

建立時間：2026-10-05 10:24 +08:00
狀態：設計提案與驗收規格，尚未實作。

## 現況與判斷

目前預設是 HeroAurora：WebGL 藍橘極光、游標透鏡、三張系統邊界／技術選型／生產落地卡片。hero-v2 仍留有多個可切換場景；舊核心方塊並非目前預設。線上桌面觀察與原始碼均支持這個判斷。

現行優點是品牌色明顯、流程概念存在、CTA 平穩。較弱的是抽象光效與卡片微動尚未讓人直接看到「你把什麼問題解決了」。在本次較窄桌面截圖中右側卡片有裁切，這可能屬於構圖；但若說明內容必須閱讀，驗收時就不能接受關鍵文字依賴裁切區。

建議保留藍橘識別與平面按鈕，把動畫主角改為**需求變成可驗證系統的過程**。不是再增加一個可切換風格，而是收斂成一個正式場景。

## 三種方向比較

| 方向 | 記憶點 | 對服務的解釋力 | 製作成本 | 建議 |
|---|---|---|---|---|
| 極光精簡 | 色彩與空間 | 中 | 低 | 最快的小改方案 |
| 需求到交付 | 一個問題逐步變成系統 | 高 | 中 | **優先推薦** |
| 8 → ∞ → 8+ 字標 | 品牌符號 | 低至中 | 中 | 留作 /show 短片頭；圖形須重新設計，不假設現有標誌就是字元 8 |

## 推薦分鏡

左側文案與按鈕從初始畫面即可閱讀，不等待動畫解鎖。右側使用簡潔的文件、資料與結果卡，裝飾不蓋在文字上。

| 時間 | 畫面 | 傳達的意義 |
|---|---|---|
| 0–0.6 秒 | 出現一張需求卡：「想讓團隊更快找到正確資料」 | 從客戶問題開始 |
| 0.6–1.4 秒 | 卡片拆成「資料來源」「權限」「驗收條件」 | 先釐清問題與限制 |
| 1.4–2.4 秒 | 三項整理成簡明流程，節點依序連起 | 設計可理解的解法 |
| 2.4–3.4 秒 | 顯示「來源可追溯」「權限可檢查」「錯誤有回退」 | 用可驗證性說明工程價值 |
| 3.4–4.2 秒 | 收成成果卡，顯示「查看案例」連結；動畫停止 | 把注意力交還證據與行動 |

上述場景標示「流程示意」。不放虛構的正確率、吞吐量、上線狀態或客戶資料。若還没有與此對應的真實案例，連到標明實驗性質的 Demo，不借用無關案例背書。

完成後以點擊「重播流程」才再次播放。hover 可高亮連線，focus／點擊提供相同資訊；說明文字使用 HTML，不只畫在 Canvas。若做多情境選擇，最多三個明確按鈕：「知識查詢」「流程自動化」「服務整合」，不要求拖曳才能操作。

## 三個入口的不同動態語氣

- **8plus 首頁**：整理、連線、驗證。穩定、精準，讓客戶理解合作方式。
- **/show**：沿用 reference 的黑、米白、螢光黃綠；約 0.8 秒字標識別或「LING8 ONLINE」。不用強制全螢幕開場，也不自動播音。
- **shuyan.art**：作品先出現，輕微揭露細節；攝影可用前後對照，但必須有鍵盤可操作替代。作品比特效重要。

reference 封面的巨大 8 與米白中文字已足夠有辨識度。網站不需照搬整張海報作為唯一文字來源；標題、節目介紹与按鈕仍用可選取文字，保持小尺寸可讀。

## 手機與減少動態模式

手機採「標題 → 副文案 → 主次行動 → 簡化流程圖」，不再把按鈕和複雜圖形硬塞左右兩欄。圖形是補充內容，觸控不用先學操作。以 360、390、768、1280、1440px 檢查不橫向溢出，320px 檢查重排與可讀性。

prefers-reduced-motion 顯示靜態最終流程並保留完整語意；離開可視範圍或分頁隱藏時停止迴圈。原專案已有 frame-loop 與降級機制，應延用後驗證，不重複造輪子。WebGL 不可用時仍有完整文案、按鈕及靜態圖。

自動開始、持續超過五秒且與其他內容並列的非必要動態，需提供暫停／停止／隱藏機制；不能只靠作業系統的 reduced-motion 設定代替頁面控制。參考 [W3C 說明](https://www.w3.org/WAI/WCAG22/Understanding/pause-stop-hide.html)。本提案入場 4.2 秒後停止，但其他背景循環也要納入檢查。

## 效能與驗收

先用 HTML＋SVG＋CSS 完成流程；需要時才加 Canvas，不先增加 3D 依賴。首屏文字、CTA 不依賴動畫資產下載；非正式場景應移至開發入口，避免正式首頁載入多套備案。

依 [Web Vitals](https://web.dev/articles/vitals) 以真實使用的第 75 百分位追蹤 LCP ≤ 2.5s、INP ≤ 200ms、CLS ≤ 0.1，分手機與桌面。這是目標，不是目前測量結果；Lighthouse 可做回歸比較，但不能單憑載入測試宣稱真實 INP 達標。

驗收問題：

1. 首次訪客不用操作動畫，能否說出你能幫誰做什麼？
2. 動畫停止後，是否仍能讀到流程與下一步？
3. 鍵盤、觸控、減少動態、無 WebGL 是否都可完成主要任務？
4. 首屏與作品之間是否有內容關聯？
5. 改版後是否增加有品質的案例閱讀與需求對話，而非只增加停留時間？

先找 5 位目標客戶做理解測試，觀察首次閱讀與尋找案例的障礙；這是質性研究，不宣稱統計顯著。若流量不大，避免同時跑多個動畫 A/B 版本。
