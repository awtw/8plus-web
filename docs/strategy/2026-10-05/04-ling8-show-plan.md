## 品牌與聲音

母品牌 8+；本人 August；網路人格靈八 LING8；主節目《靈機8動》；觀眾解題單元《靈時工》。本文件暫用數字 8 方便與封面一致，「靈機八動」可作搜尋用別名，並非宣告最終命名。

核心人格沿用 reference：「一個試圖用工程方法理解荒謬世界的人。」S0 主題為「人類沒有文件」，測試 BUG、TECH、LIFE、靈時工四類。語氣可以吐槽但最後必須留下新理解；不要把所有人際問題說成某一種人的缺陷。

網頁開場提案：**人類沒有文件，只好拆開來看看。** 說明：**靈八用工程腦聊科技、工作與日常裡說不清楚的事。沒有答案，只有版本。** 狀態若未開播，寫「S0 準備中」，不要出現假的最新集或失效訂閱按鈕。

reference 中建議把 8plus 首頁改為靈八入口，和現有工程接案任務有衝突。本方案選擇在 /show 實現這份人格與節目首頁，讓企業入口與觀眾入口各自完整；這是本次分析後的推薦，不是原文件已經定案的內容。

觀眾的預設 CTA 是觀看／收聽，不是預約工程諮詢。首頁、文章尾部與 /about 放節目入口；節目頁 footer 才放工程合作與 shuyan 作品。/show/ask 處理觀眾題目，不能直接挪用接案診斷表或 Cal.com 當投稿箱。

## 頁面布局

/show 首屏：文字標題＋節目封面＋一句定位。已開播時主按鈕「看最新一集」、次按鈕「用聲音收聽」；未開播時顯示可確認的預告，不提供假的播放功能。

往下依序為最新內容、第一次來的三集推薦、四個題材分類、靈時工入口、靈八簡介。只有一兩集時不顯示空分類篩選器。「從哪集開始」依內容代表性選，不直接把最多觀看當唯一標準。

單集頁先放一句問題、可點擊載入的播放器及 3–5 點摘要，再放章節、整理筆記、引用來源與相關集。首屏只載封面和必要文字，第三方播放器可在點擊後載入。純音訊版要能聽懂畫面中的內容；逐字稿應校對錯字、姓名與引用，不能把 AI 原始轉錄直接當可靠引述。

## 建議 Episode 內容模型

現有 Velite 只有 Post 與 Project，不在本輪直接擴充 schema。實作時新增 Episode collection，避免用一般 Post 的 slug 與文章模板硬承載媒體頁。

| 欄位 | 規則 |
|---|---|
| title、slug、summary、locale | 必填；slug 穩定不隨標題改動；第一版 zh-TW |
| season、episodeNumber、bucket | S0；集數為整數；bucket 為 BUG／TECH／LIFE／ASK |
| status | planned／recorded／published；公開查詢只讀 published |
| publishedAt | 發布時必填 ISO 時間；排程稿不能提前公開 |
| cover、coverAlt | 真實封面與描述；不要以手機帳號設定截圖作正式封面 |
| videoUrl、audioUrl、platformLinks | 可選；發布時至少有一個可用內容入口，未設定不渲染空按鈕 |
| durationSeconds | 實際成品長度；未錄製不猜測填入 |
| chapters | timeSeconds、title；依時間排序且不得超過成品長度 |
| sources | label、url、checkedAt；每集事實查核資料 |
| transcript、html | 校對逐字稿及人工整理筆記，可分開保存 |
| relatedPostSlugs | 連延伸技術文章，避免全文重複 |

slug 應避開 ask、about 等保留名稱；同集不同媒體共用單集 URL。公開頁與 metadata、靜態參數、sitemap、feed 都使用相同發布條件，未知或草稿 slug 回 404。播放器連結僅接受已允許平台的合法 HTTPS URL。

現有 /feed.xml 是文章摘要 RSS，不是具音訊 enclosure 的 Podcast 託管 feed。第一版選定 Podcast 託管服務後連結其 feed 與平台頁；不把 blog RSS 交給 Podcast 平台當節目訂閱源。平台尚未選定，本文件不指定付費方案。

## EP01 可直接展開的製作卡

題目：工程師可能是世界上最常通靈的職業。預計 20–25 分鐘，依內容長度調整。

- 0:00–0:30：情境鉤子：「這個能不能再有質感一點？」接一句「靈機8動，我是靈八。」不連做兩段介紹。
- 0:30–4:00：用匿名、可公開的需求情境，區分觀察與推測。
- 4:00–10:00：拆「目標沒說」「限制沒說」「完成的樣子沒說」三個缺口。
- 10:00–17:00：比較雙方立場：需求方缺少語言，工程師也可能太快假設答案。
- 17:00–22:00：提出可嘗試的追問：「誰要用？現在卡哪裡？什麼算變好？」
- 結尾：留下單一投稿題目「你聽過最需要通靈的一句需求是什麼？」接「我是靈八，下次再動。」

預設三支 Shorts：沒有驗收條件的有質感；順便改一下到底改多少；先問哪三句話。每支有自己的情境與結論，不以無上下文的半句話吸引點擊。

## 一人製作的工作量

建議先保留每週 8–12 小時作為假設預算：研究／提綱 2–3 小時、錄製 1–2、剪輯 3–4、筆記與發布 1–2、回覆及檢討 1。這是規劃估算，不是製作工時保證；前兩集記錄實際時間再校正。

標準包：一份研究、一次主錄製、一集音訊與影片、三支短片、一篇 500–1,000 字整理筆記。YouTube 的 6–12 分鐘重剪版是有餘力才加，不再當每集硬性追加品。

若每週只剩 4–6 小時，改雙週一集、兩支短片與一篇筆記；十集季程延長，不假装仍能十二週完成。先減頻率與衍生品，不以低品質日更補量。

## 投稿與未露臉安排

投稿只收暱稱、問題、可否匿名公開；回覆聯絡方式選填。上線前清楚告知用途與刪除聯繫方式，設 spam 限制、成功／失敗回饋；公開展示必須先人工處理，不直接顯示原始投稿。提醒勿上傳公司機密與可識別第三人的資料，分析事件不帶投稿全文。

墨鏡與光線可作角色風格，但不是匿名保證。8plus 既有本人經歷與照片，若節目連回同網域，觀眾仍可能連結身分；本方案把「暫不完整露臉」理解為演出方式，而非隱藏本人身分的要求。
